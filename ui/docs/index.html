vibeSpot Documentation

The AI-powered HubSpot CMS landing page builder. Describe a page in plain English, preview it live, then deploy to HubSpot in one click.

What is vibeSpot? #

vibeSpot is an open-source tool that turns natural language descriptions into fully functional HubSpot CMS themes. It provides a vibe coding interface: you type what you want on the left, and a live preview updates on the right. Under the hood, an AI pipeline generates native HubSpot modules complete with HubL templates, fields.json, CSS, and JavaScript — ready to deploy to any HubSpot portal.

vibeSpot also ships a CLI wizard for converting existing React or Lovable projects into HubSpot CMS themes, and a doctor command to verify your environment is correctly set up.

Prerequisites

  • Node.js 18+ — required for the runtime. Run node -v to check.
  • Git — used for version history (auto-commit after each generation). Run git --version to check.
  • An AI engine — at least one of: Claude Code CLI, Anthropic API key, OpenAI API key, Gemini API key, or Gemini/Codex CLI. See AI Engines for details.

Installation

The fastest way to get started is with npx, which downloads and runs vibeSpot without a global install:

npx vibespot

For repeated use, install globally:

npm install -g vibespot
vibespot

This starts the web UI on http://localhost:4200 and opens your browser automatically.

Quick Start

  1. Install and launch. Run npx vibespot in your terminal. The web interface opens at localhost:4200. On first run, vibeSpot detects available AI engines and prompts you to configure one if needed.
  2. Create a theme. Click New Theme on the setup screen and give it a name (e.g., my-saas-landing). This creates a working directory at ~/vibespot-themes/my-saas-landing with the standard HubSpot theme structure.
  3. Describe your page. In the chat panel, type a detailed description of the page you want. For example: "Create a SaaS landing page for a project management tool called Taskflow. Include a hero with headline and CTA, a 3-column features grid, customer logos, a pricing table with 3 tiers, testimonials, and a footer."
  4. Watch the pipeline generate. The agentic pipeline analyzes your intent, designs a CSS system, plans modules, generates each one in parallel, then validates the output. You will see real-time progress cards for each stage. The live preview updates as modules complete.
  5. Deploy to HubSpot. Click the Deploy button in the topbar. Select your HubSpot account (or add one with a Personal Access Key), and vibeSpot uploads the theme. Once complete, a celebration screen with confetti shows a direct link to create a landing page in your HubSpot portal.

The Anthropic API is the recommended engine for the best structured output quality.

  1. Sign up at console.anthropic.com and create an API key.
  2. In vibeSpot Settings → AI tab, paste the key into the Anthropic API Key field. Or set the environment variable: export ANTHROPIC_API_KEY=sk-ant-...
  3. Select Anthropic API as the engine. The default model is claude-sonnet-4-20250514.

Claude Code is a CLI tool that runs as a subprocess. It is included in your Claude Pro/Team/Enterprise subscription at no extra API cost.

  1. Install the Claude CLI: npm install -g @anthropic-ai/claude-code
  2. Authenticate: claude auth
  3. In vibeSpot Settings → AI tab → CLI Tools section, toggle Claude Code on. vibeSpot checks if the CLI is installed and authenticated. Then select Claude Code in the Engine section above.

Claude OAuth lets you use the Anthropic API through your Claude subscription without a separate API key.

  1. Make sure the Claude CLI is installed: npm install -g @anthropic-ai/claude-code
  2. Run claude setup-token and follow the browser-based auth flow.
  3. Copy the token and paste it into vibeSpot Settings → AI tab → Claude OAuth section.
⚠ Token Expiration

OAuth tokens expire periodically. If you see authentication errors, run claude setup-token again and paste the new token.

Use OpenAI's GPT-5.5 or any compatible model through the OpenAI API.

  1. Get an API key from platform.openai.com.
  2. Paste the key in Settings → AI tab → OpenAI API Key, or set export OPENAI_API_KEY=sk-...
  3. Select OpenAI API as the engine and choose your preferred model.

Google's Gemini API offers a generous free tier suitable for experimentation.

  1. Get an API key from Google AI Studio.
  2. Paste the key in Settings → AI tab → Google AI API Key, or set export GEMINI_API_KEY=... (or GOOGLE_AI_API_KEY).
  3. Select Gemini API as the engine.

The Gemini CLI runs as a local subprocess, similar to Claude Code.

  1. Install the Gemini CLI: npm install -g @google/gemini-cli
  2. Authenticate with your Google account.
  3. In vibeSpot Settings → AI tab → CLI Tools section, toggle Gemini CLI on. Then select it in the Engine section above.

OpenAI's Codex CLI runs as a subprocess, included in OpenAI subscriptions.

  1. Install the Codex CLI: npm install -g @openai/codex
  2. Authenticate with your OpenAI account.
  3. In vibeSpot Settings → AI tab → CLI Tools section, toggle Codex CLI on. Then select it in the Engine section above.

HubSpot Connection

vibeSpot uploads themes to HubSpot using one of two methods:

  • API mode (recommended) — Uses the HubSpot CMS API directly with a Personal Access Key. Uploads modules in parallel for speed. No HubSpot CLI required.
  • CLI mode (legacy) — Uses the hs CLI tool to upload sequentially. Slower but works if API mode encounters issues.
  1. Get a Personal Access Key (PAK). Go to your HubSpot portal → Settings → Account Setup → Integrations → Private Apps, or visit app.hubspot.com/personal-access-key/{portalId} directly. Create a key with the Content scope (Design Manager read/write). Copy the key (starts with pat-na1- or pat-eu1-).
  2. Add the account in vibeSpot. Open Settings → HubSpot tab → Add Account. Paste the PAK. vibeSpot validates it and detects your portal ID and data center (NA1 or EU1).
  3. Select the account. If you have multiple portals, click the one you want to deploy to. The active account is shown with a green indicator.
ℹ Multi-Account Support

You can add multiple HubSpot accounts (different portals or data centers). Switch between them in Settings → HubSpot tab before uploading. vibeSpot detects EU1 data centers automatically from your PAK prefix.

The Editor #

The vibeSpot editor is a browser-based environment for building HubSpot CMS pages. It combines a chat-driven AI assistant with a live preview and code editing capabilities.

Layout Overview

vibeSpot uses a two-mode architecture: Project Home for project selection and setup, and Editor for building pages. The active mode is controlled by a data-mode attribute and switches automatically when you open a project.

The editor has three main panels separated by a draggable resize handle:

  • Left panel (380px default) — Contains a module bar button at the top (click to open the module slideout) and the chat interface below it. The module slideout overlays the chat when open. The chat header shows the template name and active AI engine.
  • Resize handle — A 4px draggable divider between panels. Turns orange on hover. Drag to resize the left/right split. The left panel has a minimum width of 300px and maximum of 600px.
  • Right panel (fills remaining space) — Live preview of the rendered page (default), or toggle between Preview, Split, Plan, and Code views. The preview includes a slim browser chrome bar with dots and a URL display.

On tablet viewports (768–1024px), the project rail collapses to a 48px icon-only width, the chat panel narrows, and topbar labels hide to prevent clipping. On viewports below 768px, a responsive gate dialog is shown — the full editor requires a wider screen.

Workspace Tabs

The Project Home dashboard is organized into workspace tabs, each covering a distinct concern:

  • Pages — Create new pages and manage existing templates. The page tree sidebar shows all templates with type badges (LP, Blog, Web, Sec), labels, and module counts.
  • Brand — Brand kit (colors, fonts, logo URL) with a live visual preview card showing color swatches, sample text, and logo thumbnail. Also surfaces import analysis results for themes fetched from HubSpot.
  • Library — Project assets browser showing images, fonts, and scripts in the active theme. Also provides access to the shared module library for adding reusable modules to any template.
  • Marketplace — Marketplace validation and listing metadata editor.
  • Settings — Quick access to AI, HubSpot, Figma, GitHub, and vibeSpot configuration.

The topbar provides access to theme settings, upload, version history, responsive viewport toggle, and the settings gear.

Project Overview Table

When you have multiple projects, the Project Home shows a sortable table that gives you a bird's-eye view of every project in your workspace:

ColumnWhat it shows

Bulk Operations

Select multiple projects using the checkboxes in the leftmost column, or click the header checkbox to select all. A floating toolbar appears with the selection count and two actions:

  • Duplicate — Copies all selected projects (only available for projects with saved sessions).
  • Delete — Removes all selected projects. A confirmation dialog asks whether to also delete local theme files from disk.

Chat Panel

The chat panel is your primary way to interact with the AI. Type a message describing what you want and press Enter to send. Use Shift+Enter to insert a new line without sending.

During generation, the chat panel shows a real-time pipeline progress UI with stage indicators and per-module status cards. Each module progresses through: queued → generating... → validating... → ✔ (complete) or ✗ (failed). If a module fails, it may show retrying... before a second attempt.

File Attachments

You can attach files to your messages for additional context:

  • Images (up to 10 MB) — PNG, JPEG, SVG, WebP, GIF. The AI can see these via vision and use them as design references.
  • Documents — PDF, DOCX, MD, TXT. Text is extracted and provided to the AI as content context.

Drag and drop files onto the chat input, or click the attachment button to browse.

Smart Chat Suggestions

After each pipeline completion, contextual suggestion chips appear below the assistant message with follow-up actions tailored to your current page. The suggestions are filtered by which modules already exist — you won't see "Add a pricing section" if you already have one. Click a chip to send it as the next message, or ignore them and type your own prompt.

Preview Panel

The preview panel renders your page using a local HubL subset renderer. It supports variables, conditionals, loops, filters, scope_css, and require_css/require_js tags. The preview automatically refreshes when modules are updated.

Use the responsive toggle buttons in the topbar to switch viewports:

  • Desktop — 100% width
  • Tablet — 768px
  • Mobile — 375px

During AI generation, modules that are being regenerated show a working overlay with a progress indicator. Modules that have already been generated remain visible and interactive.

Split View

Click the Split button in the view toggle to show the live preview and code editor side by side in a 50/50 CSS grid layout. This is useful when you want to see how code changes affect the preview in real time. Switching between Preview, Split, Plan, and Code views is fully coordinated.

Interact Mode

The Interact toggle in the preview topbar replaces the previous separate Select and Edit modes with a single contextual mode. When active:

  • Editable elements (text, images, links) — get inline WYSIWYG editing. Click to edit directly in the preview; changes persist via the API.
  • Module containers — prefill the chat input with a contextual reference so you can describe what you want to change.

Interact mode auto-deactivates during AI generation and uses a crosshair cursor to distinguish it from normal preview interaction.

Code Editor

Switch to the code editor tab to directly edit module files. The file tree is grouped by module name, and each module contains:

  • module.html — The HubL template
  • module.css — Module-scoped CSS
  • module.js — Client-side JavaScript
  • fields.json — Field definitions for the HubSpot content editor

At the theme level, you also have access to shared.css (design system utilities) and shared.js (scroll animations, shared behaviors).

The editor uses CodeMirror 6 with syntax highlighting for HTML, CSS, JavaScript, and JSON. Save your changes with Cmd+S (or Ctrl+S on Windows/Linux) or click the Save button to write to disk and refresh the preview.

Module Sidebar

The module sidebar is a toggleable slideout panel. Click the Modules button (grid icon + count badge) at the top of the left panel to open it. The slideout slides in from the left over the chat area. Click the × button or the Modules button again to close it.

The slideout has two views that swap in place:

  • Module List (default) — Shows all modules in the current template. The header displays the title "Modules", a count badge, a + button to add modules from the library, and a close button.
  • Field Editor — Opens when you click the gear icon (⚙) on a module. Shows a back arrow to return to the module list, the module name, and a dynamic form for editing field values.

Each module item in the list has:

  • Drag handle (⠷) — Grab and drag to reorder modules. The preview updates immediately to reflect the new page order.
  • Module name — The display name of the module (e.g., "Hero Banner").
  • Edit fields (⚙ gear icon, visible on hover) — Switches the slideout to the field editor view for that module.
  • Delete (× icon, visible on hover) — Removes the module from the template after confirmation. If used in other templates, it remains in the library.

Field Editor

The field editor renders a dynamic form based on the module's fields.json. Each field type uses a specific HTML control:

  • text — Standard text input (<input type="text">)
  • richtext — Multi-line textarea (<textarea rows="3">)
  • color — Native color picker paired with a hex text input. Both stay in sync.
  • image — Text input for image URL
  • link — Text input for URL
  • number — Numeric input (<input type="number">)
  • boolean — Standard HTML checkbox (<input type="checkbox">)
  • choice — Native dropdown select populated from the field's choices array
  • group — A labeled fieldset containing child fields. Groups with "tab": "STYLE" are labeled as style fields.

All field changes are debounced at 300ms and trigger an automatic preview refresh. No manual save is needed.

Your First Page

Follow these steps to build your first landing page from scratch:

  1. Create a new theme. Click New Theme on the setup screen. Enter a kebab-case name like taskflow-landing. The editor opens with an empty canvas.
  2. Write a detailed prompt. The more specific you are, the better the result. Include the page purpose, sections you want, specific content (headlines, feature descriptions), and design preferences (colors, style). For example: "Build a landing page for Taskflow, a project management SaaS. Use a deep blue (#1a365d) and white palette. Then a pricing table with Free/Pro/Enterprise tiers. End with a testimonial carousel and a minimal footer."
  3. Watch the pipeline work. The agentic pipeline runs through four stages. You will see: intent analysis (what type of request), design system creation (CSS variables and shared styles), parallel module generation (each module built concurrently), and quality validation (auto-fixing common issues). The live preview populates incrementally as modules complete.
  4. Refine with follow-up prompts. After the initial generation, send follow-up messages to modify specific modules: "Change the hero background to a gradient from #1a365d to #2d3748" or "Add a FAQ section with 5 questions about Taskflow". The pipeline intelligently determines which modules to regenerate and which to keep.
  5. Edit fields visually. Click the Modules button to open the module slideout, then click the gear icon (⚙) on any module to open the field editor. Change headlines, body text, button labels, colors, and images without writing code. The preview updates in real time (300ms debounce).
  6. Deploy. Click the Deploy button in the topbar. Select your HubSpot account and watch the upload progress. When complete, click the link to go to your HubSpot portal and create a new landing page using your theme.

Content Types

vibeSpot supports three content types, each with its own pipeline prompts, validation rules, and starter templates:

  • Landing Page — The default. Full-width marketing pages with standard HubSpot CMS modules.
  • Email — HubSpot email templates with table-based layout, inline CSS design tokens, and MSO/VML conditional structure for Outlook compatibility. Select the Email card on the Project Home screen, choose "Email" from the page type dropdown, or use vibespot email from the CLI. The pipeline routes through email-specific prompts at every stage (architect, module developer, validator). A dedicated email client preview (envelope icon in the topbar) renders your email as it appears in Gmail, Outlook Desktop, and Apple Mail.
  • Blog — Blog templates with HubSpot blog variables (content.post_body, content.author, blog_recent_posts, etc.). Blog-specific prompts, validator auto-fix, and a pre-built Blog Content Hub starter template with 8 modules.

The intent analyzer detects the content type from your prompt (e.g. "create a welcome email" triggers the email pipeline). You can also set it explicitly via the asset-type cards on the Project Home screen or the page type dropdown.

Multi-Page Sites

vibeSpot can create full multi-page HubSpot sites from a single prompt. When the intent analyzer detects a site-level request (e.g. "build a 5-page website for a restaurant"), it uses the create_site intent to plan:

  • Shared modules — header and footer modules used across all pages
  • Per-page layouts — each page gets its own template with unique modules, a label, page type, and slug
  • Cross-page navigation — nav links between pages are validated to ensure they match actual page slugs

In the editor, a page tree sidebar replaces the old horizontal tab bar. It shows all templates with type badges (LP, Blog, Web, Sec), labels, and module counts. Click a page to switch to it — the chat, modules, and preview reload for that template. An inline creation form lets you add new pages with a type selector.

Page-scoped chat means the intent analyzer knows which page you're editing, enabling prompts like "same header as the home page" or "update all pages." The AI context includes activePageLabel and the full list of site pages.

Templates

Each theme can contain multiple templates. Templates define different page layouts that share the same module library and design system.

Supported page types:

  • Landing Page — The default. Full-width marketing pages.
  • Email — Table-based email templates with MSO/VML compatibility.
  • Blog Post — Content-focused layout with HubSpot blog variable support.
  • Website Page — Standard pages for your site (About, Contact, etc.).
  • Module Only — Generate standalone modules without a page template.

Template operations available:

  • Create — Add a new template to the theme. Each template starts with its own chat history.
  • Clone — Duplicate an existing template, including its module assignments and field values.
  • Rename — Change the template display name.
  • Delete — Remove a template. You can choose whether to also delete modules that are only used in that template, or keep them in the library.

Each template maintains its own chat history, so you can have separate conversations for different pages in the same theme.

Module Library

All generated modules live in a shared library within the theme. The module list shows which templates each module is used in (e.g., "Used in: Landing Page, About Page").

  • Add to template — Browse the library and add any existing module to the current template without regenerating it.
  • Preview before adding — See how a module looks before committing it to a template.
  • Cross-template sharing — A single module (like a navbar or footer) can be used across multiple templates. Changes to the module propagate everywhere.
  • Delete from library — Permanently remove a module and its files. This removes it from all templates that reference it.

Your First Generation #

Step-by-step walkthroughs for generating your first landing page, your first email template, editing with the module overview, and publishing to HubSpot.

Page Workflow: Landing Page from Scratch

This walkthrough creates a complete landing page and deploys it to HubSpot. Estimated time: 5–10 minutes.

  1. Launch vibeSpot. Run npx vibespot in your terminal. The web UI opens at localhost:4200.
  2. Pick an asset type. On Project Home you see six asset-type cards. Click Landing Page. A prompt input appears with the eyebrow "Landing Page" and a placeholder hint.
  3. Name your project. Type a kebab-case name (e.g. acme-launch) and press Enter. vibeSpot creates a theme directory at ~/vibespot-themes/acme-launch and opens the editor.
  4. Describe the page. In the chat panel, write a detailed prompt. Include the page purpose, sections, headlines, and design preferences. Example: 
    Build a SaaS landing page for Acme — a project management tool.
Use a dark navy (#0f172a) and white palette with orange (#f97316) accents.
Sections: hero with headline "Ship Projects Faster" and a CTA button,
3-column features grid with icons, pricing table (Free / Pro / Enterprise),
testimonial carousel, and a minimal footer with social links.
  5. Watch the pipeline. The four-stage pipeline runs:
    • Intent Analyzer — classifies your request as create and plans which modules to build.
    • Page Architect — creates a CSS design system (:root variables, shared styles) and plans module specs.
    • Module Developer — generates all modules in parallel. Each module card in the chat panel shows its status: queued → generating → complete.
    • Quality Check — validates HubL syntax, field names, and meta.json fields; auto-fixes any issues.
    The live preview populates incrementally as modules finish. Skeleton placeholders hold the position of modules still generating.
  6. Review in the preview. Once the pipeline completes, the full page renders in the preview panel. Use the responsive toggles (desktop / tablet / mobile) to check the layout at different breakpoints.
  7. Refine with follow-up prompts. Send targeted messages to iterate:
    • "Change the hero background to a gradient from #0f172a to #1e293b"
    • "Add a FAQ section with 5 questions after the pricing table"
    • "Remove the testimonial carousel"
    The pipeline only regenerates the affected modules; everything else stays intact.
  8. Deploy. Click the orange Deploy button in the topbar. Select your HubSpot account, monitor the upload progress, and click the link in the celebration screen to create a page in HubSpot. See Publishing to HubSpot below for the full flow.

AI Generation #

vibeSpot offers two generation modes: a simpler single-call mode and a multi-stage agentic pipeline. The agentic pipeline is the default and recommended mode.

Single-Call Mode

In single-call mode, the AI generates all modules in a single API request. The response contains a vibespot-modules JSON code block with all module definitions. This mode is simpler but less reliable for complex pages because the AI must produce all modules in one shot.

To use single-call mode, disable the agentic pipeline toggle in Settings → AI tab. Single-call mode may be useful for quick single-module additions or when using CLI engines that do not support structured output.

ℹ When to use single-call

Single-call mode is best for simple requests like adding a single module or making a small change. For full page generation, the agentic pipeline produces significantly better results.

Prompt Tips

✨ Writing Effective Prompts

Be specific about content. Instead of "add a features section," write "add a 3-column features section with icons for Speed (rocket icon), Security (shield icon), and Reliability (uptime chart icon), each with a headline and 2-sentence description."

Reference modules by name. After initial generation, refer to modules by their names: "modify the hero module to add a background video" or "change the pricing-table to include an Enterprise tier."

Use "modify X to..." for changes. Be explicit about what you want changed vs. what should stay the same. The AI preserves unchanged modules when you reference specific ones.

Provide color values. If you have a brand palette, include hex codes: "Use #1a365d as the primary color and #e2e8f0 as the light background."

Describe layout preferences. Mention grid columns, spacing, alignment: "Use a 2-column layout with the image on the left and text on the right."

⚠ Common Pitfalls

Avoid vague requests. "Make it look better" gives the AI little to work with. Instead specify what you want improved: "Increase the whitespace between sections and add subtle hover animations to the feature cards."

Do not overload a single prompt. If you want to create a full page and then heavily customize multiple modules, do it in steps: first generate, then refine individual modules in follow-up messages.

Brand Assets

Brand assets provide persistent context that the AI uses across all generations. They live in the theme and are sent with every pipeline call.

  • Styleguide — Design system documentation: typography, color palette, spacing scale, component styles. Upload a .md or .txt file, or let the AI extract a styleguide from your existing theme.
  • Brand Voice — Tone and messaging guidelines: formal vs. casual, target audience, key phrases, words to avoid. Ensures the AI writes copy that matches your brand.
  • Product Context — Auto-generated from your rendered theme. The AI analyzes existing modules to understand page structure, content patterns, and design conventions. Updated automatically after each generation.
  • Humanify — A toggle that strips AI-sounding copy patterns from generated content. Removes em dashes, banned words like "delve," "leverage," "cutting-edge," and "game-changing." Eliminates cliche openers like "In today's fast-paced world." Produces more natural, human-sounding text.

File Attachments

Attach files to your chat messages to give the AI additional context:

  • Images as design references — Upload screenshots, mockups, or design comps. The AI uses vision to analyze the layout, colors, typography, and structure, then generates modules that match. Supported formats: PNG, JPEG, SVG, WebP, GIF. Max 10 MB per file.
  • Documents as content context — Upload product briefs, copy documents, or content spreadsheets. Text is extracted from PDFs and DOCX files and provided to the AI as context for generating accurate, on-brand content. Supported formats: PDF, DOCX, MD, TXT.

Plan Mode #

A deliberation phase that runs before any code is generated. Plan mode turns vague briefs into well-scoped plans through guided dialogue, then runs the agentic pipeline against the approved plan as a high-fidelity design brief.

Without plan mode, vibeSpot generates immediately on every chat message — fast, but unforgiving on vague prompts. The AI guesses at audience, content, and structure, and you find out what it guessed only after a full generation cycle. Plan mode flips the order: the AI asks targeted questions first, surfaces what's missing, and only generates after you've reviewed and approved a written plan. The plan is markdown, persisted to {theme}/.vibespot/plan.md, and reviewable in a dedicated tab in the right pane.

When to Use Plan Mode

Plan mode is opt-in via a prominent Plan Mode pill above the chat input. The toggle persists across sessions in ~/.vibespot/config.json as planMode.

Use plan mode when:

  • You're starting from a vague brief. "Build a landing page for our new SaaS product" benefits hugely from elicitation before code is written.
  • Multiple stakeholders need to review. The plan is a markdown document that can be reviewed, edited, and shared before it becomes a generated theme.
  • You're doing exploratory design work. Iterating on the plan is much cheaper than iterating on generated modules.
  • You want explicit control. The plan documents every section, content choice, and CTA decision before the AI commits to code.

Skip plan mode when:

  • You're making small changes to an existing page (use the regular chat — the agentic pipeline handles modifications well).
  • You already have a detailed brief; type it directly and let the agentic pipeline run.
  • You're using a Figma design as the source of truth (use Figma Import instead).

The Flow

Plan mode follows three implicit phases. The AI tracks which phase to be in based on conversation history.

  1. Understand. Your first message in plan mode triggers an "ask first" response. The AI poses two to four high-leverage gap-filling questions: who is this for, what's the primary CTA, what content sections do you envision, what's the brand tone. The plan in the right pane is mostly TBD markers and an "Open questions" list.
  2. Research & Draft. Once you've answered the most important questions, the AI proposes a concrete plan: page goal, audience, primary CTA, a numbered module list with brief descriptions, brand and tone notes. It references existing modules and brand assets in the theme so you don't have to re-state them. It may ask one or two narrow follow-ups to fill remaining gaps.
  3. Refine. Subsequent messages tweak the plan. "Move the FAQ above the pricing." "Change the primary CTA to 'Book a demo'." The AI confirms what changed in chat and updates the plan in the pane. It only asks clarifying questions when your edit creates a new ambiguity.

Plan-mode templates (skip Understand)

For common page types, the cold-start Understand phase is unnecessary. When the Plan pane is empty, vibeSpot shows a picker of pre-canned templates — SaaS landing, e-commerce product, event registration, blog/content hub, portfolio, agency/services, restaurant. Picking one seeds .vibespot/plan.md with goal, audience, primary CTA, suggested kebab-case modules, brand/tone, and a tailored "Open questions" list. The next AI turn skips straight to those page-specific questions instead of asking generic ones. Pick Blank plan to keep the original free-form behavior.

The Plan Pane & Inline Editing

The Plan tab in the right pane (between Preview and Code) is the source of truth for the current plan. While plan mode is on, this tab auto-selects when you send a message so the latest plan is always visible.

Two modes inside the pane:

  • Read mode (default) — the markdown plan is rendered with proper headings, lists, tables, and emphasis. A persistent footer holds Approve plan and Discard & start over buttons.
  • Edit mode (pencil icon) — the rendered view becomes a textarea containing the raw markdown. Edit any section directly: rename headers, swap copy, reorder modules. Save persists your edits to plan.md and the next AI turn picks them up as context. Cancel reverts.

Inline editing is the fastest path for small fixes (typo, copy tweak, section rename). Use chat for substantive changes that need the AI to revisit assumptions.

Choice chips

When the AI asks a question with discrete answers (e.g. "What's the primary goal?"), it can emit clickable answer chips below its message: [Lead capture] [Sign-ups] [Demo bookings] [Brand awareness]. Clicking a chip sends that value as the next user message. You can always type a free-text answer instead — the chips are a shortcut, not a constraint.

Approval & Discard

vibeSpot enforces a hard write-gate while plan mode is active: the agentic pipeline is refused, even if the AI mistakenly tries to emit a module-generation block. Generation is reachable only via two explicit actions:

  • Approve plan — The plan markdown is prepended to a synthesized "Implement the approved plan." message and the agentic pipeline runs against it. The Plan tab automatically switches to Preview so you watch modules generate in place. Plan mode flips off after approval; turn it back on for the next plan.
  • Discard & start over — Clears plan.md, exits plan mode, returns the chat to normal generation. Used when you want to scrap the current direction entirely.

The plan persists across vibeSpot restarts. Open the same theme weeks later, toggle plan mode on, and your in-progress plan is right where you left it.

✨ Plan mode + brand assets

If your theme has a styleguide, brand voice, or product context loaded, the plan-mode AI uses them automatically. The plan will reference the right colors and tone without you re-stating them. After approval, the agentic pipeline gets the plan and the brand assets — double the alignment.

🔎 Web search during planning

Plan mode auto-engages Web Search when you've toggled it on in Settings → AI → AI Capabilities. The AI can look up competitor pages, industry references, or example landing pages while drafting your plan. Works on Anthropic API/OAuth and Claude Code engines.

Figma Import (Beta) #

Translate a Figma design into a HubSpot CMS theme without re-implementing it. The pipeline preserves the design's exact colors, typography, copy, and section order — the AI is used only to translate each section to HubL, not to make creative decisions.

Most AI tools that "import from Figma" treat the design as a vague reference and let the model regenerate everything. vibeSpot does the opposite: design tokens are extracted mechanically and mapped directly to CSS variables; section structure becomes module structure 1:1; per-section text is fed to the AI as field defaults. The AI's only job is to convert each section's layout into HubL syntax.

Figma Token Setup

  1. Open Figma and go to Account Settings → Personal access tokens → Generate new token. Give it a descriptive name like "vibeSpot import." Scopes needed: File content (read-only).
  2. Copy the token (it's shown only once).
  3. In vibeSpot, open Settings → Figma and paste the token. Click Test to verify it works. The token is stored locally in ~/.vibespot/config.json as figmaToken and is never sent anywhere except the Figma API.

You can also test the connection per-import: the import dialog accepts a one-off token if you don't want to save one globally.

What Gets Extracted

Click From Figma on the setup screen, paste a Figma file URL (or a specific frame URL, which scopes the import to that frame and its descendants), and click Extract. Progress streams via Server-Sent Events as the pipeline pulls data from Figma's REST API.

The extractor produces:

  • Design tokens — Colors with usage counts (most-used fill becomes --theme-color-bg, top non-bg fill becomes --theme-color-primary, etc.); typography styles grouped by role (heading vs body, with exact px sizes); spacing values (sorted unique scale: xs, sm, md, lg, xl, section); effects (box shadows and border radii ready as cssValue).
  • Section structure — Top-level frames in the file or selected frame become modules, in their original Figma order. Each section keeps its name (kebab-cased to a module name), dimensions, layout direction (horizontal/vertical/grid), item spacing, and padding.
  • Per-section content — Every text node is captured with its role (headline, subhead, body, CTA, eyebrow, etc.), font size, font weight, and verbatim text. This becomes the field defaults in the generated module.
  • Children structure — A summary of each section's children (e.g., "3 cards each containing: image, headline, body, button") so the AI knows the layout shape without trying to over-engineer it.
  • Image assets — Every embedded image is downloaded from Figma's image-export API at 2× resolution as PNG. Filenames are sanitized; the full set is shown to you for confirmation before generation.

After extraction, you see a summary screen: section count, color count, font families, and asset count. Name the theme (this becomes the kebab-case directory name and CSS-variable prefix), choose your image mode, and click Generate Page.

Image Modes

A toggle on the import screen controls how images are handled in the generated modules. Both modes copy the extracted PNGs to the theme's assets/ directory.

  • Import images as assets (default) — Modules reference images via get_asset_url("{theme}/assets/{filename}"). The page renders pixel-identically to Figma out of the box. Best when the Figma assets are the final assets you want on the live page.
  • Image fields with placeholders — Modules expose HubSpot image fields with placehold.co URLs as defaults. The Figma assets are still in assets/, but the modules don't reference them; instead, content editors swap in their own images via HubSpot's editor. Best when Figma images are mockups (stock photography, lorem ipsum imagery) and the real images will be different.

The Translation Pipeline

Figma import runs a streamlined pipeline (separate from the agentic pipeline used by chat-driven generation) optimized for fidelity:

  1. Generate shared CSS — Deterministic mapping of design tokens to :root CSS variables and utility classes ({theme}-container, {theme}-section, {theme}-grid, {theme}-btn, etc.). Lightness analysis on the dominant color auto-selects light vs dark mode defaults. Standard responsive breakpoints (mobile and tablet) are emitted automatically. No AI involved — the design tokens are the spec.
  2. Map sections to module specs — Each Figma section becomes one module spec: name (kebab-cased), description (inferred from name + content), content brief (text grouped by role with exact strings), and layout notes (layout mode, gap, padding, background color, children summary).
  3. Translate each module — For each spec, the AI is invoked once with a system prompt that explicitly forbids invention: "TRANSLATE this design to HubL. Use these exact texts as field defaults. Match colors, spacing, and layout from the design tokens." Modules are generated in parallel (concurrency limited via the same agenticConcurrency setting; default 20). Structured output via the Module Developer JSON schema ensures reliable parsing.
  4. Validate & auto-fix — The same quality-check stage as the agentic pipeline: balances HubL tags, normalizes reserved field names (name → item_name), upgrades deprecated field types, strips CDN imports.

Progress streams to the chat panel as standard pipeline events: a "Mapped N modules" decision, then per-module "Generating…" / "Module complete" entries. After the run, the live preview shows the page with the Figma colors, copy, and section order intact.

Tips & Limits

  • Use top-level frames as sections. The importer treats top-level frames in your Figma file (or in the selected frame) as the section boundary. If your design has everything in one giant frame, only that one frame becomes a module. Break your design into logical sections (Hero, Features, Pricing, Footer, etc.) as separate top-level frames for best results.
  • Name your frames meaningfully. Frame names become module names. A frame called Section 1 turns into a module called section-1; rename it to Hero so you get hero.
  • Auto-layout produces better results. Frames with auto-layout export their layout direction, gap, and padding cleanly. Free-form positioning is supported but the AI has to infer layout from coordinates, which is less reliable.
  • Figma rate limits apply. The image-export endpoint has limits; very asset-heavy files (50+ images) may take a minute or two to extract. Errors with status 429 indicate rate-limiting — wait and retry.
  • Permissions matter. The token must have access to the file. 403 errors mean the file isn't shared with the token's owner or doesn't have view permission.
  • Effects support is limited. Box shadows and border radii are extracted; gradients, blur effects, blend modes, and complex masks are ignored (HubL preview wouldn't render them faithfully anyway).
  • Re-importing replaces modules. Importing a Figma URL into an existing theme clears the active template's modules first — the import is treated as a full page replacement, not an additive merge.
✨ Workflow tip

For the highest-fidelity output: use auto-layout in Figma, name your frames as kebab-friendly section names ("Hero", "Trust Bar", "Final CTA"), and extract real copy + final imagery into the design before importing. The result is a HubSpot theme that's ready to deploy with no manual cleanup — content editors get a fully-fielded theme they just need to plug content into.

Inverse Pipeline (HubSpot → vibeSpot) #

Reverse-engineer an imported HubSpot theme so the AI understands its design system, module relationships, and round-trip risks before generating modifications.

When you import a theme via From HubSpot, vibeSpot downloads the files and loads modules into a session. The inverse pipeline goes further: it analyzes the theme's CSS, templates, and field schemas to extract structured context that the AI uses when generating additions or modifications.

What Gets Analyzed

  • Design tokens — :root CSS variables, inferred color palette (with usage counts), typography scale (family, size, weight per role), spacing tokens, border radii, and shadows. These are extracted from both the theme-level CSS and per-module stylesheets.
  • Module relationship graph — Which modules appear in which templates, shared field patterns across modules, and orphan modules (defined but unused by any template).
  • Field schema flags — Patterns that vibeSpot doesn't natively generate: HubDB bindings, deeply nested groups, repeater occurrence limits, custom widget types, conditional visibility rules. These are flagged so the AI avoids breaking them.
  • Round-trip risks — HubL macros, {% raw %} blocks, partials outside modules/, custom module.js files, and import_modules.json references. These patterns survive the round-trip but need preservation — the AI is told not to touch them.

Design Token Application

If the imported theme has no :root variables (common in older themes), the inverse analyzer can synthesize a :root block from the inferred palette and typography, populating sharedCss so the AI generates new modules that visually match the existing ones. Use the Apply tokens action in the UI or vibespot inverse --apply-tokens from the CLI.

How to Access

  • UI — After fetching a theme via From HubSpot, the import wizard shows the analysis results (tokens, module graph, risks) before you enter the editor.
  • CLI — vibespot inverse [--path <theme-dir>] [--json] [--apply-tokens]. Without --path, it uses the active theme.
  • API — GET /api/inverse/analyze and POST /api/inverse/apply-tokens routes in the web server.

  5. Create a page in HubSpot. When the upload completes, a celebration screen appears with confetti and a direct link to your HubSpot portal. Click it to open HubSpot and create a landing page using your new theme.
ℹ API vs. CLI Upload Mode

API mode (recommended) uses the HubSpot CMS API directly. It uploads modules in parallel and is significantly faster. Requires a Personal Access Key with CMS scope.

CLI mode (legacy) uses the hs upload command from the HubSpot CLI. It uploads files sequentially and is slower but can be useful as a fallback.

AI Error Fix

If auto-fix cannot resolve an upload error, the "Fix with AI" button appears. This sends the error messages to Claude, which:

  1. Scans all module files in the theme for the root cause
  2. Identifies the specific code that triggered the error
  3. Applies targeted fixes across all affected modules
  4. Retries the upload automatically

This is especially useful for HubL syntax errors, invalid field configurations, or template rendering issues that rule-based auto-fix cannot handle.

HubSpot Marketplace #

The HubSpot Marketplace has stricter requirements than a private theme upload. vibeSpot ships a Marketplace publication path that audits a generated theme and helps you collect the listing metadata you'll paste into HubSpot's submission form.

Where to find it

In the editor topbar, click the storefront icon (next to the version history clock) to open the Marketplace panel. From the CLI, run vibespot marketplace check.

What gets validated

  • theme.json — HubSpot's required fields (label, preview_path, screenshot_path, version, documentation_url, license, example_url, enable_domain_stylesheets, is_available_for_new_content) and the author block (name, email, url).
  • Modules — every meta.json needs a label; every field needs a label; help_text is recommended.
  • Screenshot — the path declared in theme.json must point to an existing PNG/JPG.
  • No CDN imports — @import url(https://…), <link href="https://…">, <script src="https://…"> are flagged.
  • No portal-specific URLs — hard-coded hubfs, hubspotusercontent, or portal preview URLs are flagged.
  • Accessibility baseline — <img> tags need alt, modules should use semantic tags.
  • Listing metadata — a marketplace.json sidecar with category, description, features, support URL.

Auto-fixable findings

A subset of findings can be patched without user input — missing module labels and missing field labels (vibeSpot fills in human-readable defaults derived from the slug or field name), and external CDN @import/<link>/<script> references (stripped from CSS and module HTML). Click Apply fixes in the panel, or run vibespot marketplace check --fix.

Listing metadata editor

Click Edit listing in the panel (or run vibespot marketplace edit) to fill in the values that go on the Marketplace listing page: category, description, features, support URL, documentation URL, pricing tier. The values are written to a marketplace.json sidecar at the theme root and are picked up by the validator.

Submitting to HubSpot

vibeSpot does not submit the theme for you — that requires HubSpot Partner API access and a manual review process. Instead:

  1. Run the Marketplace check until it passes.
  2. Upload the theme to your developer portal with Deploy (or vibespot upload).
  3. In your HubSpot developer portal, open Marketplace listings → Submit new listing and paste the values from marketplace.json.
  4. HubSpot reviews the listing and the theme on their side; address any feedback they send back.
✨ Screenshots

HubSpot expects a 1500×1000 PNG at screenshot_path plus additional listing images uploaded directly through the portal. vibeSpot validates that the file exists; capturing it is up to you for now.

Version History #

vibeSpot automatically tracks every generation as a git commit in the theme directory. This gives you a full timeline of changes with the ability to roll back to any previous state.

How It Works

Each time the AI pipeline generates or modifies modules, vibeSpot creates a git commit in the theme's local repository. The commit message describes what changed (e.g., "Generated hero, features, pricing, footer" or "Modified hero: updated headline and background color"). No manual saving is required.

Browsing Versions

The compact history timeline sits above the chat input — each pill is one generation step, labeled with the user message that produced it. The currently active version is highlighted. Hover any pill to see the commit hash, age, and the section names changed in that step.

For the deeper view, click the clock icon in the topbar to open the full version history panel with:

  • Timestamp for each version
  • Description of what changed
  • Per-template filtering to see changes for a specific template

Rolling Back

Click any pill in the timeline (or any entry in the history panel) to restore the theme to that point. This is a non-destructive operation: vibeSpot creates a new commit that reverts to the selected state, so you never lose the intermediate history. You can always go forward again to a newer version.

Keyboard Shortcuts

Press Ctrl+Z (Cmd+Z on macOS) to step back one version, or Ctrl+Y / Ctrl+Shift+Z to step forward. Shortcuts are ignored while the chat input or any other text field is focused, and while the AI is generating.

✨ Tip

Use the timeline as a fast undo. If an AI generation goes in the wrong direction, hit Ctrl+Z to revert and try a different prompt.

Troubleshooting #

Common issues and how to resolve them:

vibeSpot could not detect any configured AI engine. You need at least one of the following:

  • Install the Claude Code CLI: npm install -g @anthropic-ai/claude-code then claude auth
  • Add an Anthropic API key in Settings → AI tab or via export ANTHROPIC_API_KEY=sk-ant-...
  • Add an OpenAI or Gemini API key

Run vibespot doctor to see a full diagnostic of available engines.

Upload failures are usually caused by one of:

  • Invalid PAK permissions. Your Personal Access Key needs the CMS scope (Design Manager read/write). Regenerate the key with the correct permissions.
  • HubL syntax errors. The auto-fix system handles most of these automatically. If it does not, click "Fix with AI" to let Claude diagnose and repair the issue.
  • CLI mode issues. If using CLI mode, try switching to API mode in Settings → HubSpot tab. API mode is more reliable.

Check the error message in the upload progress panel for specific details.

When the Anthropic API returns a rate limit error, vibeSpot automatically retries with exponential backoff. The retry intervals are: 10 seconds, 20 seconds, 40 seconds, 60 seconds, and 120 seconds. In most cases the request succeeds on retry without any action needed.

If rate limiting persists, you may be hitting your account's rate cap. Consider upgrading your Anthropic plan or reducing agenticConcurrency in your config to lower the number of parallel API calls.

OAuth tokens have a limited lifespan. When the token expires, generation fails with an authentication error.

To fix: run claude setup-token in your terminal, complete the browser-based authentication, and paste the new token into Settings → AI tab → Claude OAuth section.

If a module appears blank or broken in the preview, check:

  • fields.json validity. Open the module's fields.json in the code editor and verify it is valid JSON. A trailing comma or mismatched bracket will cause parsing failure.
  • HubL syntax. Look for unbalanced tags (e.g., {% if %} without {% endif %}). The quality check catches most of these, but manual edits can introduce new issues.
  • JavaScript errors. Open the browser console (Cmd+Option+J) to check for runtime errors in the module's JS.

The most common causes of CSS not applying:

  • Missing theme prefix. All CSS classes should be prefixed with the theme name (e.g., .my-theme-hero__title). Without the prefix, styles may conflict with HubSpot's global CSS or be too generic to match.
  • CDN imports stripped. External @import statements (like Google Fonts) are automatically removed because HubSpot does not allow CDN imports. Use system fonts or self-hosted alternatives.
  • Scoped CSS issues. The scope_css HubL tag wraps module CSS in a scope. Make sure your selectors work within this scope.

Occasionally the preview iframe can get into a stale state during rapid generation cycles. To fix:

  • Hard refresh the page with Cmd+Shift+R (or Ctrl+Shift+R) to clear the browser cache.
  • If the issue persists, check the browser console for errors. An incomplete WebSocket reconnection can sometimes stall preview updates.
